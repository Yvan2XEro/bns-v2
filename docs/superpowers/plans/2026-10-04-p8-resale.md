# P8 Resale Implementation Plan

> **For agentic workers:** Execute task-by-task against the binding spec. Write a failing behavior test before implementation and keep the integrated feature branch uncommitted until the user-requested final commit.

**Goal:** Implement the supplier-to-reseller marketplace end to end without holding third-party funds, preserving P4 as the only order writer and P5 as the protected-payment and payout source of truth.

**Architecture:** `services/resale.ts` owns resale eligibility, terms, links, listings, and holds. `services/purchaseOrders.ts` owns purchase orders, reseller commissions, charges, and payouts; it calls P4/P5 services and the registered resale-adjuster port, never writes order status directly. Search grouping runs in the search-indexer from published events; web and mobile consume typed API projections.

**Tech Stack:** Payload CMS 3 + MongoDB transactions, Next.js routes, Bun workspaces, Vitest API integration tests, Meilisearch, Redis, NotchPay, Next-intl and i18next.

**Spec:** `docs/superpowers/specs/2026-09-15-p8-resale-design.md` (binding authority).

## Global Constraints

- No duplicate stock or supplier product content in reseller listings.
- The supplier remains the seller of record; the storefront and packing slip carry reseller branding.
- BuyNSellem never holds third-party funds; COD resale commission payout is BuyNSellem's own payable.
- P4 `applyTransition` and action functions remain the only order writers.
- Supplier/reseller prices and `supplierUnitPrice` never enter public listing/search/buyer projections.
- Eligibility and all feature flags fail closed; prepaid stays disabled without P5 and the written NotchPay gate.
- Transactions include all related writes and audit events; external effects run after commit.
- Client copy uses synchronized French/English next-intl and i18next messages; no hard-coded UI copy.
- Follow repository types, query, forms, access, and test-runner rules in `AGENTS.md`.

## Review Focus

- Concurrent first-resell requests must create one listing/link and never duplicate purchase orders.
- Price, eligibility, and terms changes between catalogue view and checkout must be revalidated atomically.
- Every order projection must name the supplier as seller of record and must mask recipient data after the specified 30-day period.
- Refund, return, COD refusal, and payout reversal must adjust commissions/charges idempotently without double ledger postings.
- Search grouping must preserve a visible in-stock product if every eligible representative is temporarily unavailable.

## Task Sequence

### Task 1: Collections, settings, capabilities, and generated types

Create the seven domain collections specified in P8: `ResaleLinks`, `ResaleTerms`, `ResaleTermsAcceptances`, `PurchaseOrders`, `ResellerCommissions`, `ResellerCharges`, and `ResellerPayouts`. Resale gate evidence belongs in the single `AppSettings` global; there is no separate `ResaleGates` collection. Extend products, variants, listings, order-items, commission-lines, shops, AppSettings, and Payload registration exactly per the spec. Add indexes/access matrices, `resell` capability and feature gates. Tests pin fields/defaults/indexes/access and fail-closed flags. Run `bun run generate:types` after collection registration.

### Task 2: Terms, eligibility, links, and supplier resale settings

Implement current-version terms lookup/acceptance (append-only), verified supplier/reseller eligibility, link request/approval/suspend/revoke/re-request transitions, approval-required and risk-hold behavior, and supplier settings/pricing validation. Test same-owner/self-link refusal, acceptance versioning, role permissions, all pricing boundaries, and transaction rollback.

### Task 3: Reseller catalogue, listing creation, holds, and availability

Implement reseller catalogue projections, first-resell/link behavior, one resale listing per `(shop, product)`, reseller-only variant prices, supplier-derived content, status/hold derivation, live supplier stock/availability, supplier price-change notices and effective holds. Test duplicate races, private price leakage, hold add/remove and automatic re-publication.

### Task 4: Checkout, purchase-order creation, projections, and lifecycle

Revalidate all resale eligibility/pricing/stock at placement; enforce one fulfilling shop per P4 order; snapshot terms/link/prices and create one purchase order idempotently from the accepted-order handler. Implement purchase-order views and recipient masking, accept/expire/ship/handover/failure/return/cancel actions through P4, packing slip HTML, and P7 shipment interop. Test full lifecycle, permissions, idempotency, timeout, stock, route validation, and exact worked example.

### Task 5: COD invoices, commissions, refund/return adjustments, and reverse netting

Extend P4 commission accrual/invoices for supplier `charge` and `resale_margin` lines, VAT and compensation reason exclusions. Create reseller commission snapshots, payable/held/cancelled/clawed-back transitions, supplier invoice gating, P6 refund/return adjustments through the P8 adjuster, COD refusal charges and idempotency. Assert the spec's 9,000/6,000/3,000/560/2,440/578/3,578 XAF example and transaction-failure rollback.

### Task 6: Reseller charges, payout accounts, NotchPay transfers, and jobs

Implement charge offset/overdue/pay, reseller payout planning with minimum, 25,000 XAF new-reseller cap, 500,000 XAF approval threshold, fees and active payout-account/data-protection gates. Add NotchPay transfer adapter/`RP-` webhook dispatch, payout transitions/retries, schedules and jobs. Test double webhook delivery, failure/reversal, cap ordering, offsets and ledger invariants.

### Task 7: Search indexing and representative selection

Extend listing documents and filter settings; index supplier-derived resale listing content without supplier price; implement product-group representative selection, event-driven and nightly recomputation, global/similar/search-alert representative filtering, and pin Meilisearch image version. Test deterministic daily rotation, tiering, stock/orderability, fallback and batch updates.

### Task 8: Anti-collusion, moderation, risk signals, and notifications

Enforce phone/identity self-dealing checks, supplier handover-at-premises signals, buyer concentration/cancellation/refusal holds, commission payout holds/caps, moderation transitions and the full P8 notification set. Publish risk signals through the P9 outbox port. Test normalized phone matching, threshold boundaries, audience-specific push routes, event idempotency and role permissions.

### Task 9: Web and mobile supplier/reseller experiences

Implement supplier settings/catalogue/link management, reseller catalogue/resell/pricing, supplier/reseller purchase-order inbox/detail/actions, packing slip print/share, commissions/charges/payouts and status dashboards. Add routes/deep links, React Query hooks, form schemas, loading/empty/error states, responsive/mobile accessibility and complete FR/EN parity. Tests pin pure flow/permissions and payload view usage.

### Task 10: End-to-end gate audit and release verification

Trace COD and gated protected orders from catalogue through payout/refund; verify every P8 spec section, endpoint, job, workflow, translation and invariant against implementation. Run focused suites, all API/web/mobile/search-indexer suites, type checks, generated-type check, exact AGENTS.md ceilings, Biome and `git diff --check`; fix defects with regression tests. Keep any external NotchPay confirmation and user-operated staging/payment checks explicitly identified as external prerequisites.
