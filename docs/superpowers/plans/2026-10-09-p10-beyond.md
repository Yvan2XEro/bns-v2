# P10 Beyond Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote every launch-market fact that lives in code — `douala`/`yaounde` city keys, `+2376\d{8}`, `Africa/Douala`, `"XAF"` and `FCFA` literals, cron hours written as "Douala minus one", XAF amounts on global settings — into one `markets` registry plus a `market-cities` collection, exactly as P5 promoted provider, settlement mode and VAT. Thread the market's currency from cart to quote to order to intent to ledger to invoices to both clients' formatters, with no FX anywhere. Split the multi-shop cart at checkout into one order per `(storefront shop, fulfilling shop)` group behind `multiShopCartEnabled`, all-or-nothing, one payment intent per order, P5's money invariants untouched. The international rule ships as CI: a new market is rows — market row, city rows, amounts, formatting table, review evidence — never a code change, and `market-literals.guard.spec.ts` fails the build on any retired literal.

**Architecture: a strangler over the literals, in a fixed order.** The registry lands first (collections, loader), the hydration second (`getPaymentSettings` assembles its `MarketRow[]` from the collection behind its unchanged signature; `launchCities` becomes a shim), the call-site migrations third (currency, cities, timezones, crons, clients — batched per surface), and the literals guard **last**, because it fails the build on literals the migrations retire. Until the user turns `multiShopCartEnabled` on, the CM market must read **byte-identically**: same cart shape, same quotes, same formatted strings, same invoice bytes, same cron effects — the migration's golden fixtures and the flag-off parity pins are the proof, not a promise. Fail-closed everywhere: an unknown or non-`live` market refuses (`market.unknown`, `market.notLive`); the CM fallback dies with the literals.

**Tech Stack:** Payload CMS 3.79 + MongoDB transactions (`packages/api`, vitest via `bun run test:int`), Next.js + next-intl `{x}` (`packages/web`), Expo + i18next `{{x}}` (`packages/mobile`), both clients `bun test`.

**Spec:** `docs/superpowers/specs/2026-10-09-p10-beyond-design.md` — the binding authority for every domain rule: its Assumptions M1–M9, its error codes, its Review focus and Testing sections. Its Decisions-for-the-user (formatting approval, markets to seed, rounding per currency, per-market amounts, cart bounds, feature posture, per-order protection fee, copy veto) are **gates recorded in Task 26's release record, not tasks** — nothing in this plan waits on them: CM seeds the already-approved behaviour and the M6 bounds ship at 5/30 pending confirmation.

## Global Constraints

Copied from the spec and AGENTS.md; every task's requirements implicitly include this section.

- **The CM market reads byte-identically while the flag is off.** With `multiShopCartEnabled: false` and only CM `live`, every existing int suite (P4 checkout, P5 payments, P7 delivery, P8 resale) passes unmodified; `cart.singleShop`/`cart.singleFulfilment` keep firing; `GET /api/cart` and `POST /api/checkout/quote` answer today's shapes; the CM golden fixtures (quotes, formatted strings, invoice PDFs, cron effects) are byte-identical pre/post migration (Task 7 pins them). Any task that cannot hold this parity is wrong, not the parity.
- **Fail-closed market resolution.** An invalid market document is dropped, not repaired (the `marketOf` discipline, quoted in `lib/paymentSettings.ts:135-139`: "a guessed currency or VAT rate on a live market would be charged to buyers"). Checkout, quote, cart-add, intent creation and public config resolve the market first and refuse (`market.unknown`, `market.notLive`); nothing ever defaults to CM/XAF. The client's `?country=` is presentational only — the server derives the market from the cart's listing shop and the delivery city.
- **One market, one currency, no FX.** `Money` is integer minor units. The currency is read once per flow from the market and copied forward; nothing downstream re-derives it. Any attempt to combine two currencies — a posting, an invoice line, a cart — is a thrown error, never a conversion.
- **P5's money rules are untouched.** `getPaymentSettings`, `isProtectedPaymentOpen`, `resolveSettlement`, the G1–G6 gates, the env kill-switch and `paymentSettingsRefusal` keep their signatures and semantics — P10 moves the **rows**, not the rules. No intent covers more than one order; exposure caps, commission, protection fee, settlement, payouts, refunds, disputes stay per order. The split multiplies orders, never touches a money rule.
- **The ledger has one writer.** `services/ledger.ts` stays the only module that posts. P10 adds exactly one refusal there (Task 11) and zero posting kinds. `services/stock.ts` stays the only stock writer; order status writes go only through `applyTransition`.
- **Transactions and after-commit.** The split placement is one Payload transaction (`lib/transactions.ts`, shared `req`, 3 retries on `TransientTransactionError`); sequence numbers come from `nextNumber` **outside** it (the landed rule — gaps allowed); provider calls and Novu triggers after commit.

## Review Focus

The seven failure modes from the spec, most likely first. Each line's pinning test is assigned to the owning task.

1. **A cart split racing stock.** Two buyers place groups sharing a variant's last unit; reservations are conditional atomic updates in globally sorted variant order, so one transaction loses, throws `checkout.stockChanged`, and rolls back *all* its orders — no sibling order of the losing placement survives, no reservation leaks. Test: concurrent placements over a 1-unit variant; exactly one group of orders exists and `stockReserved` totals are exact. → Task 16's race pin.
2. **A market row missing a field.** The loader drops imperfect rows, so a market mangled by a raw DB edit becomes *unknown*, not *default*: each required field invalidated in turn ⇒ `market.unknown` on every money path, never a fallback value. → Task 4's fail-closed matrix (loader), re-asserted on config by Task 9 and on place by Task 16.
3. **Currency mismatch refused at the ledger.** A posting whose `currency` differs from its order's `amounts.currency` throws `LedgerPostingError`, caught by nothing; account keys already carry currency, so even a bug past the check cannot net XAF against another currency; reconciliation runs per currency and flags the gap. → Task 11's mismatch pin.
4. **The single-fulfilment invariant surviving the split.** The cart refusal becomes a per-order placement assertion (`order.mixedFulfilment`) re-checked by the per-group quote precondition: a corrupted group with two fulfilling shops aborts the whole placement loudly. → Task 16's integrity-harness pin (Task 15 re-asserts the quote precondition).
5. **A spoofed or stale `?country=`.** Presentational only; a mismatched query parameter changes nothing charged. → Task 9's spoof pin.
6. **Partial payment of a group.** One sibling paid, one expired: each order's P5 lifecycle runs alone; the paid order ships, the expired one releases its stock; no cross-order clawback exists to get wrong. → Task 17's group test.
7. **Formatting row absent for a locale, or the migration moving a rendered string.** M9 renders `"XAF 1 410"`-style explicit code, never a silent `FCFA`; golden tests pin CM's exact current strings so the migration cannot change one rendered amount. → Task 2 (the M9 fallback and the CM goldens), Task 7 (the pre/post migration byte pin).

```ts
export interface Money { amount: number; currency: string }
export interface MoneyFormat { locale: "fr" | "en"; symbol: string; position: "before" | "after";
  groupSeparator: string; decimalSeparator: string; minorUnit: number }

const SPACE_CLASS = /^\s$/;

export function formatMoney(amount: number, format: MoneyFormat): string {
  const sign = amount < 0 ? "-" : "";
  const abs = Math.trunc(Math.abs(amount));
  const base = 10 ** format.minorUnit;
  const major = String(Math.trunc(abs / base)).replace(/\B(?=(\d{3})+(?!\d))/g, format.groupSeparator);
  const minor = format.minorUnit > 0
    ? `${format.decimalSeparator}${String(abs % base).padStart(format.minorUnit, "0")}` : "";
  // The digits↔symbol joiner is not a stored field: French typography reuses
  // the narrow no-break space it groups with, English a plain space. A
  // space-class groupSeparator is reused, anything else falls back to U+0020
  // (Conflicts 2 — the spec's MoneyFormat carries no joiner).
  const join = SPACE_CLASS.test(format.groupSeparator) ? format.groupSeparator : " ";
  return format.position === "before"
    ? `${sign}${format.symbol}${join}${major}${minor}` : `${sign}${major}${minor}${join}${format.symbol}`;
}

/** M9: explicit, ugly, never a silent FCFA — "XAF 1 410" (code first, plain-space groups). */
export function formatMoneyFallback(amount: number, currencyCode: string, minorUnit: number): string;
```

## Conflicts found while planning

The plan follows AGENTS.md: int specs under vitest, client suites under `bun test`. The spec's sentence reads as "Bun-era tooling", not a runner instruction; flagged for the amendment list.
2. **`MoneyFormat` carries no digits↔symbol joiner**, yet the CM goldens need U+202F in French and U+0020 in English. Task 7 copies every existing counter to its `:CM` sibling at the same value before Task 12 switches readers; asserted by next-value continuity.
